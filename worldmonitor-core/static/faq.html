Frequently Asked Questions

Answers to the questions people most often ask about WorldMonitor Core. Short answers first, longer background in llms-full.txt.

Product

What problem does WorldMonitor Core solve?

A real-time awareness feed — the kind a 24/7 ops center would run on a wall monitor — but affordable to self-host and small enough to embed in another product. One Rust binary, three open feeds, a sensible default severity model.

Where does the data come from?

Three open sources: GDELT 2.1 (global events, machine-coded), NASA EONET v3 (natural events), and a curated RSS set including Reuters, AP, ArsTechnica, KrebsOnSecurity, SpaceNews, Al Jazeera, RFI and BBC. Country briefs are summarized by a hosted LLM on Groq.

Is the LLM involved in severity scoring?

No. Severity is a deterministic function of feature detectors in the Rust core. The LLM is only used to compose the per-country natural-language brief when a user asks for one, which keeps scoring reproducible and auditable.

How are alerts delivered?

Each ingestion tick runs the new-event batch against every alert subscription. A match (country + severity threshold) enqueues a dispatch to the user's Slack webhook or Telegram bot, keyed by (user_id, event_id) so an overlapping re-fusion never notifies twice.

How much history do I get?

Free: 7 days. Pro: 90 days with full-text search and CSV export. Enterprise: up to 365 days via the API.

Access & identity

What tier do I need for API access?

Enterprise ($49/month). Keys are prefixed wm_, scoped to one account, hashed with PBKDF2 before storage, and revocable from the Settings UI. Send as Authorization: Bearer wm_… or X-API-Key: wm_….

How do I sign in on another device?

By default each browser is its own account (UUID in localStorage). To follow your account across devices, open Settings → Account Sync and link a handle + passphrase. Then sign in on the other browser with the same pair.

Can I self-host it?

Yes. The Rust binary is the only moving part. SQLite is embedded; there is no external database or queue. A Dockerfile is in the repo root. Minimum requirements: one small VM or container with ~256 MB of RAM and outbound HTTPS.

AI agents & retrieval

What AI agents and LLM crawlers are allowed?

All public AI and search crawlers are allowed. robots.txt enumerates GPTBot, OAI-SearchBot, ClaudeBot, PerplexityBot, Google-Extended, Googlebot, Bingbot, Applebot, CCBot, cohere-ai, Bytespider and others. Only /api/ paths are disallowed.

Can I wire this up to ChatGPT Actions or a Claude Agent?

Yes. The service publishes an OpenAPI 3.1 spec and a ChatGPT plugin manifest. Point your agent runner at either and it will self-configure. See the API docs for a worked example.

Trust

What's the licensing / privacy stance?

The service is proprietary; the engagement contract depends on tier. Source is at github.com/dnzengou/wm-agents-claude. We do not sell user data; per-browser identity is just a UUID; passphrases are stored as PBKDF2 hashes with per-record salt, never plaintext. Stripe handles billing — card numbers never touch our servers.

Where do I report a security issue?

See /.well-known/security.txt (RFC 9116). Coordinated disclosure via GitHub Security Advisories is preferred.
