About WorldMonitor Core

A real-time awareness feed for the kinds of events a 24/7 ops center would track — but affordable to self-host and small enough to embed in another product.

Why it exists

Most tools for real-time geopolitical / cyber / natural-event awareness fall in one of two camps: enterprise threat-intelligence platforms costing tens of thousands a year, or DIY stacks the user has to assemble themselves. WorldMonitor Core splits the difference. It is one open-source binary that fuses three public feeds into a single severity-scored map, with an LLM-written country brief one click away.

How it works

The ingestion layer pulls GDELT 2.1 geo-events, NASA EONET v3 natural events, and a curated RSS set (Reuters, AP, ArsTechnica, KrebsOnSecurity, SpaceNews, Al Jazeera, RFI, BBC) every 15 minutes, classifies each item into a domain (geopolitical, natural, cyber, nuclear, …), scores severity 1–10 deterministically using feature detectors, deduplicates by headline hash, and batch-inserts the survivors into an embedded SQLite database. A Tokio broadcast channel then fans the new batch to every connected Server-Sent-Events subscriber without polling, and the Atom feed and JSON API are regenerated from the same cache.

Transparency & trust

  • Deterministic scoring. Severity is a function of feature detectors, not an LLM — reproducible across restarts and auditable in source.
  • Attribution. Every event card links back to its upstream source URL. We classify and index, we don't republish.
  • Security. Stripe webhooks verified with HMAC-SHA256. Credential comparisons constant-time. Passphrases stored as PBKDF2-SHA256 with per-record random salt. Coordinated-disclosure contact at /.well-known/security.txt.
  • Privacy. Per-browser identity is a UUID in localStorage. Linking an account stores a handle + salt + hash, never the passphrase.
  • Open-source. Repo: github.com/dnzengou/wm-agents-claude.

Architecture highlights

Rust · Axum SQLite (embedded) Tokio broadcast SSE PBKDF2 · HMAC-SHA256 Preact + htm (no bundler) No CDN OpenAPI 3.1 Atom 1.0 · JSON-LD · llms.txt

One Rust binary. SQLite embedded. No queue, no cluster. ~256 MB of RAM and outbound HTTPS are enough. The frontend is Preact + htm vendored at /vendor/*.mjs — no CDN dependency, no bundler step, works offline after first load.

For AI agents

The service is designed to be driven by AI agents as a first-class client, not just by a browser. Three artifacts make that trivial: the OpenAPI 3.1 spec, the ChatGPT Actions manifest, and the Atom 1.0 feed. See the API docs or llms-full.txt.
